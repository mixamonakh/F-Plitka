# Элит-Плит

Сайт услуг по укладке плитки «Элит-Плит» — https://elit-plit.ru. Дизайн реализован по `design_handoff_elit_plit/README.md` от 14.10.2026: React 19 + Vite, Montserrat / Fira Sans, графит и золото, реальные фотографии из репозитория. При сборке React генерирует готовый HTML каждой страницы, который затем становится интерактивным в браузере.

## Локальный запуск

Node.js 24 LTS (версия указана в `.nvmrc`).

```sh
npm ci
npm run dev
```

Сайт: <http://127.0.0.1:5173/>. Редактировать нужно файлы в `src/`, а не результат сборки в `dist/`.

```sh
npm run check       # ESLint, тесты, сборка, аудит локальных ссылок и изображений
npm run build       # готовый статический сайт в dist/
npm run preview     # просмотр сборки на http://127.0.0.1:4173/
npm run start:api   # отдельный Node.js-обработчик заявок на 127.0.0.1:3001
npm audit           # проверка зависимостей
```

`npm run audit:site` проверяет уже собранный `dist/`: ссылки и якоря, дубли ID, подписи полей, вложенные интерактивные элементы, изображения в HTML/CSS и декодирование файлов. Результат — `reports/site-audit.json`. Внешние сервисы в эту команду не входят; результаты их проверки указаны в [AUDIT.md](AUDIT.md).

Для проверки поведения через Playwright MCP: открыть локальный сайт, затем выполнить `browser_run_code_unsafe` с `filename`, указывающим на `scripts/browser-smoke.js`. Проверка использует адрес текущей вкладки, проходит новые страницы на 390/1280 px, дополнительные размеры 320/768/1440 px, меню с клавиатуры, фильтры, перенос из прайса, калькулятор, сохранение версий, форму адреса, 301 и 404. Проверять следует собранный сайт через `npm run preview`, поскольку проверяются canonical и пререндер. Реальные заявки не отправляются. Браузерный профиль из AGENTS.md — основной; отдельный `/Users/misha/.codex/browser-profiles/F-Plitka` использован с разрешения владельца.

## Структура

- `src/App.jsx` — общая структура страниц и модальная заявка.
- `src/components/HandoffPages.jsx`, `SiteLayout.jsx`, `ServiceGrid.jsx` — страницы, шапка, подвал и общие блоки handoff.
- `src/components/EstimateCalculator.jsx`, `PriceTable.jsx`, `ProjectGallery.jsx` — интерактивные расчёты, прайс и портфолио.
- `src/components/LeadForm.jsx`, `Dialog.jsx`, `Navigation.jsx` — существующие формы и диалоги с новой навигацией.
- `src/content/*.jsx` — сохранённые тексты и секции исходного сайта, общие блоки используются повторно.
- `src/content/pages.js` — метаданные, 10 услуг, навигация, перенаправления и единая матрица ставок.
- `src/content/catalog.js` — тексты handoff, состав работ, FAQ и фотографии проектов. Неизвестные параметры проектов оставлены пустыми.
- `src/content/site.js` — логотип, название в шапке, телефон и Telegram общих компонентов. Название также используется в текстах и метаданных страниц.
- `src/lib/` — расчёт стоимости, соответствие URL страницам, управление анимациями.
- `server/` — единственный маршрут `POST /api/contact`, проверка формы, доставка в Telegram и SMTP. В браузерную сборку не входит.
- `src/sass/` — БЭМ-стили на Sass `@use`; палитра бренда определена в `base/_variables.scss`.
- `src/sass/handoff.scss` — адаптивные БЭМ-стили новых страниц, состояний и печати.
- `src/styles.css` — сохранённые стили доступности, диалогов и анимаций.
- `public/` — локальные изображения и иконки. Шрифты собираются из npm; анимации реализованы локально в CSS без отдельной библиотеки.
- `scripts/prerender.mjs` — генерация HTML, метаданных и файлов для поисковых систем.
- `tests/` — проверки расчётов и сохранённых URL.

`dist/`, `reports/` и промежуточная `.prerender/` не хранятся в Git. Старые исходники доступны в истории репозитория.

Исходный логотип сохранён в `public/icons/logo-original.png` (968 × 658). В шапке используется прозрачный `logo.webp` в исходном разрешении; размеры отображения задаёт `src/components/Hero.css` с сохранением пропорций. PNG-версии и favicon подготовлены из того же исходника; для маленьких иконок используется монограмма без надписи.

## Калькулятор

Одна чистая функция `calculateEstimate` используется на главной, в подробном режиме, прайсе и серверной обработке. Считаются выбранные стены с вычетом двери, либо готовые площади. Режимы сохраняют параметры. Прайс передаёт выбранные операции с их единицами, отдельно от геометрии комнаты. Комплекс душевого поддона заменяет входящие операции; повторное начисление блокируется и на сервере.

Скидка 10% при заказе с сайта применяется один раз, как в handoff; купон `7778` подтверждает ту же скидку. Подготовка, затирка, гидроизоляция, запилы и другие операции без утверждённой ставки явно показаны «по смете». Когда все позиции неизвестны, итог также «по смете». Запас увеличивает только количество плитки. Форматы: 200×200, 300×600, 600×600, 600×1200.

«Сохранить расчёт» записывает версию с UUID, параметрами, датой создания и прайса в localStorage этого браузера. Доступны файл JSON и ссылка с параметрами без адреса. Это не серверное хранилище. При передаче заявки сервер пересчитывает ставки. Если дата прайса изменилась, восстановление показывает уведомление о пересчёте. «Скачать PDF» открывает системную печать с отдельным печатным оформлением сметы; выбрать «Сохранить как PDF».

События `calculation_start`, `calculation_result`, `calculation_save`, `estimate_request`, `contact_confirmed` передаются через `elit-plit:analytics` и `window.dataLayer`. В параметрах только имя события и режим; телефон, адрес и остальные поля заявки не передаются. Счётчик сторонней аналитики не подключался.

## Анимации

Контент ниже первого экрана появляется один раз: 480 мс, сдвиг вверх не более 16 px. Эффект запускается, когда в поле зрения вошла заметная часть блока (15% внутри области с нижним отступом 80 px). Карточки в строке на большом экране появляются с интервалом 60 мс. Текст первого экрана появляется в той же манере; фон, навигация и формы доступны сразу. Портфолио появляется целой группой, без увеличения отдельных фотографий. Наведение меняет цвет за 160 мс, прозрачность фотографий — за 220 мс. Меню и модальные окна появляются за 220 мс. Вращений, масштабирования и анимации высоты нет. Параметры задаются переменными `--motion-*` в `src/styles.css`.

`prefers-reduced-motion: reduce` отключает анимации, переходы, плавную прокрутку и автопереключение первого слайдера. Настройка учитывается и при смене без перезагрузки. При клавиатурном фокусе блок показывается сразу; без JavaScript или IntersectionObserver контент не скрывается.

## Формы

Заявки используют существующий `POST /api/contact`. Форма «Проверьте свой адрес» готовит текст с адресом, этажом и лифтом: посетитель копирует его и самостоятельно отправляет в Telegram; телефон для этого не нужен. Поля сохранены: `service`, `address`, `square`, `email`, `name`, `phone`, `check` (булево согласие). Обязательны услуга из существующего списка, телефон и согласие. Для ступеней поле `square` содержит длину в погонных метрах, для остальных услуг — площадь в м². Остальные поля необязательны. Заявка из калькулятора дополнительно передаёт `calculation: { id, createdAt, priceDate, parameters }`. Сервер нормализует параметры и заново рассчитывает ставки, скидку и итог; значения цены и итога от клиента не используются. В Telegram/SMTP попадают ID, параметры, версия прайса, известные строки и список «по смете». Тело запроса — JSON, не более 8 КБ; запрос принимается только с разрешённого Origin. Получателей задаёт сервер, посетитель не может их изменить.

Каждая заявка одновременно отправляется боту `@elit_plit_bot` в группу «Элит-Плит — заявки» и через SMTP на фиксированный адрес `19aikkan85@gmail.com`. HTTP 200 с `{ "ok": true }` возвращается, когда хотя бы один канал подтвердил приём. Подтверждение SMTP означает приём письма почтовым сервером, а не прочтение или попадание во «Входящие». При отказе обоих каналов возвращается ошибка, введённые данные сохраняются. Во время отправки поля и кнопка заблокированы. После успеха форма очищается, согласие снимается.

Одинаковые одновременные запросы объединяются; успешная заявка не отправляется повторно в течение минуты в рамках одного процесса. Очереди, базы данных и автоматических повторов нет. Если один канал недоступен, второй продолжает работать; недоставленная копия автоматически не досылается. При неопределённом сетевом результате форма предлагает связаться напрямую, не повторяя запрос автоматически. В журнал попадают только канал, результат и ID подтверждения; текст заявки и секреты не журналируются.

`npm run dev` и `npm run preview` подключают настоящий обработчик через Vite, без подмены Telegram/SMTP. Настройки загружаются из `.env`, `.env.local`, `.env.production`, `.env.production.local` в этом порядке; окружение процесса имеет приоритет. После изменения секретов перезапустите локальный сервер. Не используйте префикс `VITE_` для секретов. Нужны `TG_BOT_TOKEN`, `TG_CHAT_ID`, `SMTP_HOST`, `SMTP_USER`, `SMTP_PASSWORD`; `SMTP_PORT` по умолчанию 465, `SMTP_FROM` по умолчанию совпадает с `SMTP_USER`. SMTP всегда использует TLS. Контактная почта в публичном тексте остаётся только в политике конфиденциальности; отправка писем выполняется сервером.

PHP/PHPMailer не используются. **Старый SMTP-пароль присутствовал в Git: если он ещё действующий, его нужно сменить у почтового провайдера.** Удаление файлов не удаляет пароль из истории.

## Публикация

Домен `https://elit-plit.ru` задан в локальном `.env.production`. Этот файл также содержит `TG_BOT_TOKEN`, исключён из Git и не должен попадать в `dist/` или публичный каталог сервера. Пример публичных настроек хранится в `.env.example`. При необходимости адрес сборки можно переопределить через окружение:

```sh
SITE_URL=https://elit-plit.ru npm run build
```

При заданном `SITE_URL` создаются canonical, `og:url`, абсолютный `og:image`, `sitemap.xml` и ссылка на sitemap в `robots.txt`. Без домена не подставляется ни старый, ни выдуманный домен; canonical и sitemap пропускаются.

В публичный каталог размещается **только содержимое `dist/`**. Новые URL собираются в каталоги с `index.html`. Сервер должен отдавать их напрямую, отсутствующие адреса — с HTTP 404 и подготовленным `404.html`. Общий fallback на главную не нужен. Сборка генерирует `.htaccess` для Apache, `_redirects` для совместимых статических хостингов и `legacy-redirects.nginx.conf` для включения внутрь Nginx server block. Используйте конфигурацию своего сервера: наличие файла само по себе не включает правила Nginx. Query-параметры сохраняются. Локальные dev/preview применяют те же 301 и настоящий 404.

Для форм дополнительно нужен процесс Node.js (`npm run start:api`) вне публичного каталога: `server/`, `src/content/` и `src/lib/calculator.js`, `package.json`, `package-lock.json`, зависимости (`npm ci --omit=dev`) и приватная конфигурация. `SITE_URL` обработчика должен совпадать с фактическим origin сайта. API слушает только `127.0.0.1`, порт задаёт `CONTACT_PORT` (по умолчанию 3001). Nginx должен направлять только этот маршрут в Node.js:

```nginx
location = /api/contact {
    client_max_body_size 8k;
    proxy_pass http://127.0.0.1:3001;
    proxy_set_header Host $host;
    proxy_read_timeout 45s;
}
```

Перед публичным включением обработчика настройте ограничение частоты запросов в Nginx. Эти изменения подготовлены локально; серверная конфигурация и публикация в рамках подключения не выполнялись.

Тестовая версия: <http://elit-plit.monakhov.tech/>. Статическая сборка размещается на `monakhov-tech-server` в `/var/www/elit-plit.monakhov.tech`; Nginx возвращает `X-Robots-Tag: noindex, nofollow, noarchive`. На тесте используется HTTP, HTTPS для этого поддомена не настроен. Продакшен `elit-plit.ru` в рамках этой работы не обновлялся.

Сборка для теста сохраняет его существующие метаданные: `SITE_URL=https://elit-plit.monakhov.tech npm run build`. Значение в `.env.production` при этом не меняется. Перед обновлением теста сохраняется резервная копия его каталога в `/var/backups/elit-plit/`.

Телефон и Telegram обновлены по данным владельца; MAX пока указан номером без ссылки на профиль. Адрес сохранён. Цены калькуляторов обновлены, ступени считаются за погонный метр; скидка 10% по купону `7778` сохранена. Telegram и SMTP подключены к локальному обработчику.
